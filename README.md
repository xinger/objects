# Objects

Статическая библиотека изображений на Astro: категории, сетка, отдельные страницы
объектов, скачивание оригиналов и светлая/тёмная тема. Адрес сайта:
https://objects.xinger.net.

## Разработка

Нужен Node.js 22.12+; проект проверен на Node.js 24.

```sh
npm ci
npm run dev
```

Сайт доступен на http://127.0.0.1:4321.

```sh
npm test
npm run check
npm run build
npm run preview
```

Браузерные проверки запускаются командой `npm run test:ui` и требуют установленного
Google Chrome. Они создают собственный временный каталог внутри игнорируемой
папки `media/`; production-данные остаются неизменными.

## Каталог

`data/categories.json` задаёт названия и порядок категорий:

```json
[
  { "id": "furniture", "title": "Мебель" }
]
```

Для каждой категории нужен `data/categories/<id>.json` с массивом объектов.
Пустая категория содержит `[]`.

```json
[
  {
    "id": "obj_000001",
    "original": "originals/obj_000001.png",
    "preview": "previews/obj_000001.webp",
    "width": 2048,
    "height": 2048,
    "title": "Красный стул",
    "description": "",
    "tags": [],
    "filename": "red-chair.png"
  }
]
```

`title`, `description`, `tags` и `filename` необязательны. Размеры описывают
оригинал; превью должно сохранять его пропорции. ID уникален во всём каталоге
и задаёт постоянный адрес `/object/<id>/`. Категория определяется файлом.
Порядок объектов соответствует порядку записей в массиве; общий каталог
объединяет категории в порядке из `categories.json`.

Ключ `original` относится к https://objects-media.xinger.net/, `preview` — к
https://objects-previews.xinger.net/. Можно указывать полные HTTP(S)-адреса.
Для своих адресов задайте публичные переменные `PUBLIC_MEDIA_BASE_URL` и
`PUBLIC_PREVIEW_BASE_URL` в `.env` и настройках сборки Cloudflare. Если задана
только первая переменная, оба типа изображений используют её: это удобно
для локального просмотра. Секреты в эти переменные не кладутся.

Изображения храните вне Git: локально в `media/`, опубликованные — в Cloudflare
Workers Static Assets. Сначала загрузите оригиналы и превью, затем добавьте JSON
и сделайте push в `main`. Сборка проверяет данные и создаёт страницы по 60
объектов, страницы каждого объекта, sitemap изображений и robots.txt.
Новые данные требуют пересборки.

## Локальный просмотр с временными изображениями

При наличии подготовленного каталога `media/demo-data/` и PNG в
`media/preview-public/media/`:

```sh
CATALOG_DATA_DIR=media/demo-data PUBLIC_MEDIA_BASE_URL=/media/ PREVIEW_PUBLIC_DIR=media/preview-public npm run dev -- --ignore-lock
```

Эти переменные нужны только локальному preview. Обычная production-сборка читает
`data/` и копирует только `public/`, без временных PNG и тестового каталога.

## Cloudflare: сайт и изображения

Сайт работает в Cloudflare Pages, проект `objects`. Git integration подключена
к `xinger/objects`, production-ветка — `main`. Push в `main` автоматически
собирает и публикует сайт и JSON каталога. Технический адрес:
https://objects-6bn.pages.dev/.

Настройки Pages: `npm run build`, папка `dist`, `NODE_VERSION=24`,
custom domain `objects.xinger.net`.

Для изображений созданы два приложения **Workers Static Assets** на Free:

| Приложение | Адрес | Файлы |
| --- | --- | --- |
| `objects-originals` | `objects-media.xinger.net` | `originals/**/*.png` |
| `objects-previews` | `objects-previews.xinger.net` | `previews/**/*.webp` |

Конфигурации находятся в `cloudflare/`. Приложения раздают статические файлы
без Worker-кода, R2 и базы данных. Статические запросы и хранение assets бесплатны:
https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/.
Платные подписки для этой схемы не нужны.

Ограничения Free: 20 000 файлов на приложение, до 25 MiB на один файл.
Команда загрузки резервирует один файл для проверки доступности и допускает
до 19 999 PNG и 19 999 WebP. Все размеры, количества и пары PNG/WebP проверяются
**до** публикации. При превышении лимита команда завершится с ошибкой;
увеличивать тариф или менять оригинал она не будет.

CORS и скачивание настроены через `cloudflare/*.headers`. Оригиналы имеют
`Content-Disposition: attachment`; JavaScript сохраняет полученный Blob без
преобразования. Превью отображаются обычными изображениями. Изображения кешируются
на год, поэтому при замене файла используйте новый ключ, например `chair-v2.png`.

## Публикация изображений

```sh
npm run images:preview -- media/originals media/previews
npm run images:deploy -- media/originals media/previews --dry-run
npm run images:deploy -- media/originals media/previews
```

Первая команда создаёт WebP. Вторая проверяет локальную подготовку публикации,
ничего не отправляя в Cloudflare. Третья загружает весь набор PNG и WebP,
сохраняя вложенные папки. Например, локальный `media/originals/chairs/one.png`
станет `https://objects-media.xinger.net/originals/chairs/one.png`.
Превью `media/previews/chairs/one.webp` станет
`https://objects-previews.xinger.net/previews/chairs/one.webp`.

Указывайте папки **со всей коллекцией**: очередная публикация заменяет текущий
набор файлов. Если удалить файл локально, после публикации его адрес перестанет
работать. Пустые папки команда не публикует. Папка WebP должна содержать ровно
по одному превью на каждый PNG; после удаления PNG удалите его старое WebP.
Прочие обычные файлы игнорируются, символические ссылки запрещены.

При подготовке создаются временные копии внутри игнорируемой `media/`.
Нужно свободное место на диске примерно на размер PNG и WebP; копии удаляются
после выполнения команды. Исходные файлы не изменяются. Обновление двух
приложений последовательное: если одно не удалось, повторите команду,
а JSON публикуйте после успешной загрузки обоих.

Изображения не публикуются через push в Git. После загрузки файлов добавьте
записи в JSON и сделайте push в `main`, чтобы они появились на сайте.

## Инструменты Cloudflare

Официальный CLI Wrangler установлен как локальная зависимость разработки.
Его версия фиксируется в `package-lock.json`.

```sh
npm ci
npm run cf -- --version
npm run cf -- login
npm run cf -- whoami
```

Вход выполняется через браузер. После входа Wrangler позволяет публиковать
изображения и управлять Cloudflare через терминал. R2 для проекта не используется.

Локальные исходники и подготовленные превью можно хранить в `media/`:
эта папка исключена из Git. Файлы `.env`, `.dev.vars` и локальное состояние
Wrangler также исключены из Git.

Документация: https://developers.cloudflare.com/workers/wrangler/

## Превью тяжёлых PNG

Перед публикацией создайте WebP локально:

```sh
npm run images:preview -- media/originals media/previews
```

Команда обходит вложенные папки, сохраняет их структуру и меняет расширение
`.png` на `.webp`. По умолчанию результат записывается в `media/previews/`.
Длинная сторона — максимум 1024 px, пропорции и прозрачность сохраняются,
маленькие изображения не увеличиваются. Качество WebP — 82, alpha — 100.
Обрабатываются четыре файла одновременно; исходные PNG остаются без изменений.
Повторный запуск заменяет существующие WebP. Не указывайте чужую папку с WebP
как папку результата.

В JSON поле `preview` указывает на подготовленный WebP, `original` — на PNG.
Файлы загружаются в отдельные приложения Static Assets; конвертация не выполняется в браузере или при
сборке сайта. Изображения из `media/` не попадают в Git и production-сборку.

## Импорт из папок

Категории в `data/categories.json` должны соответствовать именам папок внутри
папки источника. Для первоначальной коллекции:

```sh
npm run images:import -- "/Users/xinger/Documents/New project"
npm run images:deploy -- media/library/originals media/library/previews
```

Импорт копирует PNG в игнорируемую `media/library/originals/`, создаёт прозрачные
WebP в `media/library/previews/` и записывает JSON по одному файлу на категорию.
Исходные папки и PNG не изменяются. В папке результата нужны место для копий
и отсутствие старых файлов: для следующего полного импорта укажите новую папку
вторым аргументом и используйте её при публикации.

При наличии `prompts.txt` записи сопоставляются по полному имени PNG либо по
номерному префиксу. Из промпта извлекаются название, описание и подходящие теги;
команды генерации, ограничения и требования к кадрированию исключаются.
Если соответствующего промпта нет, название берётся из имени файла,
описание и теги остаются пустыми. Тексты сохраняются на языке исходников.
Дубли ключей в промптах и неподдерживаемые имена PNG останавливают импорт.

ID страницы создаётся из категории и исходного имени файла, после импорта
он хранится в JSON. При ручном переносе объекта в другую категорию сохраняйте ID.
Ключи PNG/WebP включают хеш содержимого PNG: замена содержимого не оставит старую
картинку в годовом кеше. Исходное имя сохраняется для скачивания.
Импорт полностью заменяет JSON перечисленных категорий; ручные правки текста
лучше делать после него. Перед push проверяйте сборку и публикуйте изображения.

## Главная и общая лента

Главная `/` и `/all/` показывают одну общую ленту из всех категорий вперемешку.
Каждая сборка получает новый случайный seed и заново перемешивает общую ленту.
Порядок определяется SHA-256 от `objects-feed-v1:<seed>:<id>`. Один seed используется
для всех страниц сборки: главная, `/all/` и бесконечный скролл согласованы, обновление
страницы не меняет порядок. Отдельный список ID или перемешивание в браузере не нужны.
Категории остаются фильтрами в навигации и сохраняют порядок записей из JSON.

Общая лента находится на `/all/`, следующие страницы — `/all/page/2/` и далее.
Старые адреса `/page/2/` перенаправляются на новые через Cloudflare `_redirects`.
Ленты категорий сохраняют прежние адреса и бесконечный скролл.
